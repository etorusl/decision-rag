# H100: запуск и сравнение

Это инструкция для **одной H100 80 GB**, Linux и Python 3.12. Локально на Mac проверены
данные, алгоритм, метрики и tiny-model forward/backward; CUDA проверяется первым шагом на сервере.

## Окружение

```bash
git clone git@github.com:etorusl/decision-rag.git
cd decision-rag
bash scripts/setup_h100.sh
source .venv/bin/activate
```

Если Python имеет другое имя: `DECISION_RAG_PYTHON=python3 bash scripts/setup_h100.sh`;
допустимы Python 3.11–3.13. CUDA 12.8 wheel требует совместимого NVIDIA driver;
при ошибке драйвера исправьте окружение до запуска моделей. Скрипт использует PyTorch 2.7.1,
Transformers 4.57.1 и зафиксированные core dependencies из `constraints-h100.txt`.
`environment-h100.txt` сохраняет полный установленный набор.

```bash
python scripts/h100_preflight.py --json-output results/h100-preflight.json
pytest tests/test_local_backend.py -q
```

Preflight не скачивает модели: проверяет FP32/BF16 FlexAttention с вопросами и options,
сброс позиций, gradient checkpointing и совпадение градиентов с dense mask на маленькой Qwen3.
На настоящих длинных запросах всё равно нужен замер VRAM. Flex mask compilation может зависеть
от формы запроса; `--warmup 2` не гарантирует прогрев всех возможных размеров. Поэтому храните
сырые per-query latency и дополнительно делайте cold run с `--warmup 0` в другом output.

## Быстрое сравнение без обучения

```bash
bash scripts/benchmark_h100.sh multidoc2dial 100
bash scripts/benchmark_h100.sh conditionalqa 100
```

Каждая команда запускает BM25, Qwen3-Embedding-8B, dense + Qwen3-Reranker-8B top-100,
Qwen3-8B binary и Qwen3-8B binary + choice. Модели запускаются последовательно;
для dense+reranker обе модели находятся на GPU одновременно. Offline dense index сохраняется
и проверяется по хешу корпуса и имени модели; saved query candidates не используются.
Поиск по vectors выполняется точно на CPU и входит в latency.

Для более дешёвой диагностики:

```bash
EMBEDDING_MODEL=Qwen/Qwen3-Embedding-0.6B \
RERANKER_MODEL=Qwen/Qwen3-Reranker-0.6B \
NAIVE_MODEL=Qwen/Qwen3-0.6B \
bash scripts/benchmark_h100.sh multidoc2dial 20
```

Это отдельная конфигурация, её нельзя смешивать с 8B строками в сравнении.
`100` означает source-order prefix запросов, **полный корпус сохраняется**.
Для итоговых результатов замените `100` на `all`.

## Обучение

```bash
bash scripts/train_h100.sh multidoc2dial smoke
bash scripts/train_h100.sh multidoc2dial full
bash scripts/train_h100.sh conditionalqa full
```

Две задачи обучаются отдельно. Это независимая supervised recipe: BM25 hard negatives,
симулированная память только внутри training examples, 3% train-dialogues для мониторинга MD2D
и 10% training pages CQA. Вопросы без paragraph evidence CQA дают page-stage supervision.
Dev/validation/test никогда не используются для обучения. Контрольные группы отделяются до
создания примеров. Для повторения: фиксированный seed 42, хеши inputs и параметры в manifest.

`smoke`: первые 500 training queries, два head-only шага и 10 LoRA updates, затем 20 evaluation queries.
Это проверка работоспособности, не полноценное обучение. `full`: все training queries,
200 head-only шагов, затем одна эпоха LoRA, r=64 / alpha=128, LR=1e-4.
Обучение начинается с Qwen3-8B-Base, **не** с general-trained checkpoint из статьи.
Поэтому цифры 60.7 R@1 и прочие результаты trained модели статьи не являются обещанием.

Для оценки своего checkpoint:

```bash
decision-rag benchmark \
  --corpus data/multidoc2dial/corpus.jsonl \
  --queries data/multidoc2dial/queries.jsonl \
  --preset multidoc2dial --backend head \
  --checkpoint checkpoints/REPLACE_WITH_ACTUAL_DIRECTORY \
  --choice-k 0 --warmup 2 --output results/trained-md2d-full
```

Периодические checkpoints пригодны для inference. Optimizer-state resume пока отсутствует;
не прерывайте полное обучение, рассчитывая возобновить optimizer с того же шага.

## Если не хватает памяти

По умолчанию `max_request_tokens=30000`, `max_context_tokens=32768`, `max_packed_tokens=40960`.
Первый предел учитывает совместный текст и вопросы; второй — позиции контекста/самой длинной ветки;
третий — все физически упакованные токены. Модель никогда молча не отрезает контекст.

Снизьте запрос до 8k и число кандидатов, сохранив это в конфигурации эксперимента:

```bash
decision-rag benchmark \
  --corpus data/multidoc2dial/corpus.jsonl --queries data/multidoc2dial/queries.jsonl \
  --preset multidoc2dial --backend hf --limit 100 \
  --max-request-tokens 8000 --max-candidates 64 \
  --max-context-tokens 8192 --max-packed-tokens 16384 \
  --output results/naive-small-context
```

При обучении заново создайте records с `training-data --max-tokens 8000 --max-candidates 64`,
а trainer запустите с `--max-context-tokens 8192 --max-packed-tokens 16384`.
Изменение batch/context — измеряемая абляция: качество может поменяться.
Полный AdamW fine-tuning 8B (`--mode full`) не является рекомендуемым режимом для одной H100;
LoRA и head-only доступны без распределённой инфраструктуры.

## Протокол итогового сравнения

- Все системы: одни и те же query IDs, corpus hash, top-k, hardware и relevance labels.
- Качество: R@1/5/10, Hit@1, nDCG@5/10, MRR. Queries без evidence не входят в retrieval quality,
  но входят в latency; количество таких queries записано отдельно.
- Скорость: per-query p50/p95/p99, serial QPS, peak allocated/reserved VRAM и tokens/forward passes.
  Инициализация модели и offline indexing исключены из retrieval time.
- Cold и warmed-up latency храните отдельно. Запускайте несколько повторов с разным `RUN_TAG`.
- Confidence intervals: `decision-rag compare RUN_A RUN_B --metric recall@1`; для диалогов
  resampling идёт целыми conversations, а не независимыми turns.
- MTRAG: official gold-only метрики не равны expanded relevance из статьи.
- NQ: собственные cluster summaries и выборка не считаются точной авторской конфигурацией.

```bash
RUN_TAG=repeat1 bash scripts/benchmark_h100.sh multidoc2dial all
RUN_TAG=repeat2 bash scripts/benchmark_h100.sh multidoc2dial all
python scripts/summarize_runs.py results
```

В ходе timing нет кэша ответов. Повторный output не перезаписывается — используйте новый run tag.
Для latency не запускайте несколько GPU-экспериментов одновременно на одной H100.
